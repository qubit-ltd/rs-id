# rs-id 0.3 design

## Goals

- Eliminate duplicate allocation races in classic Snowflake and Sonyflake.
- Use `parking_lot::Mutex` for every generator that owns synchronized mutable
  allocation state.
- Make Qubit Snowflake decoding independent of a preconfigured generator.
- Define uniqueness, identifier ownership, restart, clock rollback, and
  blocking behavior precisely in Rustdoc and both READMEs.

## Allocation state

Each Snowflake-family generator owns `Mutex<Option<TimeSlice>>`. A timestamp and
sequence pair is reserved only while holding that mutex. If the current time
slice is exhausted, the caller releases the mutex, waits for a later physical
time slice, and retries the reservation. It never writes a timestamp/sequence
pair after reacquiring the mutex without checking the state again.

`None` is a startup fence. On first use, the generator marks the currently
observed time slice exhausted and waits for the next slice before allocating.
Consequently a stopped instance can be replaced by a new instance with the same
epoch and node identity without repeating IDs from the current slice, provided
the physical clock has not moved backwards.

Classic Snowflake and Sonyflake reject a clock rollback immediately. Qubit
Snowflake keeps its configured bounded rollback wait. Sequence exhaustion and
the startup fence normally block for at most one time unit, but a stalled clock
can block indefinitely.

## Qubit layout API

`QubitSnowflakeBuilder` becomes `QubitSnowflakeLayout`, because the type
describes an immutable bit layout rather than a stateful builder. `build`
becomes `compose`, and `QubitSnowflakeGenerator::builder` becomes `layout`.

`QubitSnowflakeLayout::decode(id)` first decodes the fixed mode and precision
header bits, derives the remaining field widths, and returns
`QubitSnowflakeParts { mode, precision, timestamp, host, sequence }`. Decoding
is therefore independent of a generator configuration. Stateless `compose`,
`decode`, and `generate_at` calls do not promise uniqueness.

## Uniqueness contract

For Snowflake-family generators, successful `next_id` and `next_string` calls
on one live shared instance never repeat. Applications should share one
instance per process and per ID namespace. Concurrent instances must have
exclusive host/node/machine identifiers across processes and servers.

Replacing a stopped instance with the same identity and epoch is safe only when
the machine clock has not moved backwards. No in-memory generator can preserve
this guarantee across an actual clock rollback without persisted allocation
state or coordination outside this crate.

Mica UUID-like values use 128 random bits. Their uniqueness is probabilistic,
not absolute, and the generator owns no synchronized mutable allocation state.
